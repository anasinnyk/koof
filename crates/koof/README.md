# koof

Runtime for Kubernetes operators generated by [`koof-gen`](https://crates.io/crates/koof-gen)
from an OpenAPI document and overlays.

A generated provider describes each resource as a static `ResourceDescriptor`
(API operations, identifiers, references, credentials); `koof` does the rest:

- reconciles managed resources Crossplane-style: observe, create, update, delete,
  late initialization, drift detection, `managementPolicies` and `deletionPolicy`;
- resolves path parameters, request bodies and credentials from referenced
  resources (`zoneRef`, `accountRef`, ...) and Secrets;
- reports `Ready` / `Synced` conditions, events and `atProvider` status;
- serves Prometheus metrics, `/healthz` and `/readyz`.

## Usage

The provider binary is a few lines around the generated code:

```rust,ignore
use my_provider::generated::{PROVIDER, controllers};

#[tokio::main]
async fn main() -> Result<(), koof::AppError> {
    koof::App::new(&PROVIDER).with(controllers).run().await
}
```

`run` installs the TLS provider, initialises logging (`RUST_LOG`), reads the
configuration from the environment, connects to Kubernetes and stops on `SIGTERM`
or Ctrl-C. To keep those under the binary's control, use `run_with`, which only
serves the endpoints and runs the controllers until the given future completes:

```rust,ignore
let config = koof::config::Config::defaults(&PROVIDER);
let client = kube::Client::try_default().await?;
koof::App::new(&PROVIDER)
    .with(controllers)
    .run_with(config, client, shutdown)
    .await?;
```

On shutdown the controllers stop taking new events and let running reconciles
finish; a controller still running 20 seconds later is aborted.

## Features

| Feature      | Default | Enables                                                    |
|--------------|---------|------------------------------------------------------------|
| `env`        | yes     | `Config::from_env` (`KOOF_*` variables) used by `run`      |
| `subscriber` | yes     | `tracing-subscriber` logging initialised by `run`          |
| `fake`       | no      | `koof::fake`, the in-memory provider API for e2e tests     |

## Configuration

Settings are resolved in layers, later wins: built-in defaults, the provider's
defaults from `x-kube-provider.http` in its overlay, then environment variables.
Durations are written like `30s`, `1m30s` or `500ms`. The resolved configuration is
logged at startup; an invalid value stops the binary.

| Variable                           | Default                     | Purpose                                     |
|------------------------------------|-----------------------------|---------------------------------------------|
| `KOOF_BASE_URL`                    | the OpenAPI server URL      | Base URL of the provider API                |
| `KOOF_METRICS_ADDR`                | `0.0.0.0:8080`              | Metrics, health and readiness endpoints     |
| `KOOF_POD_NAME`                    | –                           | Instance name reported on events            |
| `KOOF_CONCURRENCY`                 | `8`                         | Parallel reconciles per resource kind       |
| `KOOF_HTTP__TIMEOUT`               | `30s`                       | Whole provider API request                  |
| `KOOF_HTTP__CONNECT_TIMEOUT`       | `10s`                       | Connecting to the provider API              |
| `KOOF_HTTP__POOL_IDLE_TIMEOUT`     | `90s`                       | How long an idle connection is kept         |
| `KOOF_HTTP__POOL_MAX_IDLE_PER_HOST` | `16`                        | Idle connections kept per host              |
| `KOOF_HTTP__USER_AGENT`            | `koof-<provider>/<version>` | `User-Agent` of provider API requests       |
| `KOOF_LEADER_ELECTION__ENABLED`    | `false`                     | Run controllers only while holding a Lease  |
| `KOOF_LEADER_ELECTION__NAME`       | `koof-<provider>`           | Name of the `coordination.k8s.io` Lease     |
| `KOOF_LEADER_ELECTION__NAMESPACE`  | the pod's namespace         | Namespace of the Lease                      |
| `KOOF_LEADER_ELECTION__LEASE_DURATION` | `15s`                   | How long a lease is valid without renewal   |
| `KOOF_LEADER_ELECTION__RENEW_INTERVAL` | `5s`                    | How often the lease is renewed or retried   |
| `KOOF_FAKE_ADDR`                   | `0.0.0.0:8081`              | Address of the `fake` test API binary       |
| `RUST_LOG`                         | `info`                      | Log filter                                  |

## Replicas and leader election

Without leader election every instance reconciles every object, so a provider
must run as a single replica: `deploy/base` uses `replicas: 1` and the `Recreate`
strategy. To run more replicas, or a `RollingUpdate` strategy, set
`KOOF_LEADER_ELECTION__ENABLED=true`.

With leader election enabled, each instance serves `/healthz` and `/metrics`
immediately, while `/readyz` reports not ready until it holds the Lease. The
holder identity is `KOOF_POD_NAME`, else the hostname. Only the holder runs the
controllers; it renews the Lease every `RENEW_INTERVAL` with
`resourceVersion`-guarded updates, and a standby takes over once the Lease has not
changed for `LEASE_DURATION`. When the holder cannot renew within
`LEASE_DURATION - RENEW_INTERVAL`, or finds another holder, it stops the controllers
through the graceful shutdown path and exits with an error so that it is restarted
as a standby. On a normal shutdown the Lease is released, so a standby takes over
at once. The namespace is resolved from `KOOF_LEADER_ELECTION__NAMESPACE`,
`POD_NAMESPACE` (set by `deploy/base`) or the service account namespace file; the
binary stops when none is available.

The Lease is covered by a namespaced `Role` generated next to the `ClusterRole`
and bound in `deploy/base`: `get` and `update` only on the Lease named
`koof-<provider>`, and `create` (which cannot be limited by name) in the provider's
namespace. A custom `KOOF_LEADER_ELECTION__NAME` or `KOOF_LEADER_ELECTION__NAMESPACE`
needs matching RBAC.

## Compatibility

Code generated by `koof-gen` uses the `koof` API of the same minor version: keep
both at the same `0.x` release.
